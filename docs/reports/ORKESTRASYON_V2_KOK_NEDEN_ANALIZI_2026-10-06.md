# Orkestrasyon V2 ve Codex Subagent Hataları — Kök Neden Analizi

## Kapsam ve yöntem

Kullanıcının isteğiyle üç sağlayıcıdan ayrı rollerle read-only analiz alındı:

- Gemini 3.8 Flash: olası nedenleri hipotez olarak üretti. Workspace-read capability available idi; araç/terminal veya web kullanılmadı. İlk model attempt'i timeout oldu, adapter retry'siyle görev tamamlandı. Gemini çıktısı kesin bulgu sayılmadı.
- Space Bunny Free: ilk geniş inceleme iki timeout attempt'i sonrası sonuç vermedi. Daha dar kapsamlı read-only inceleme tamamlandı; bu çıktı da ana orkestratör tarafından kaynakta doğrulanmadan kabul edilmedi.
- DeepSeek V4 Pro: yerel kod analizi yaptı, dosya değiştirmedi ve web/terminal kullanmadı.

Ana orkestratör ayrıca güncel kaynak ve regresyonları kontrol etti. GPT-6.1 Sol'un önceki V2 üretim-hazırlığı bulguları düzeltme kapsamını belirledi. Sağlayıcıların görüşleri danışmanlık olarak ele alındı; tek başına kanıt kabul edilmedi.

## Sonuç özeti

Kod kaynaklı V2 bulgularının düzeltmeleri ve testleri mevcut. Önceki `auth_invalid` olayının tarihsel provider kök nedeni ise raw stdout/stderr kaydedilmediğinden bilinmiyor. Düzeltilmiş sınıflandırıcı, geçmiş çağrının gerçekte yanlış pozitif olduğunu kanıtlamaz; yalnızca aynı geniş regex kaynaklı yanlış sınıflandırmayı önler.

## Kaynakla doğrulanan nedenler

1. **Codex `auth_invalid` yanlış pozitif mekanizması:** Eski regex, ilgisiz `author`, `authorization` ve `oauth` alt dizelerini authentication failure olarak eşleştirebiliyordu. `codex-adapter.js` artık belirgin authentication-failure ifadelerini sınıflandırıyor; `tests/faz-3-codex.test.js` bu üç sözcük için negatif regresyonlar içeriyor. 2026-10-05 olayının ham provider çıktısı mevcut değil; olayı bu mekanizmaya bağlamak mümkün değil. Aynı modelle daha sonraki live read-only görev başarılı oldu; bu, geçmiş çağrının nedenini açıklamıyor.

2. **`provider-windows-gates` görevinin `blocked` sonucu provider arızası değildi:** İlk brief, shell/CLI gerektiğinde durmayı açıkça emrediyordu; worker bu stop condition'a uydu. Sonraki prompt, yalnızca listelenmiş snapshot dosyalarını read-only araçlarla okumaya izin verdi ve task-specific stop condition'ların önceliğini korudu. `parallel-batch.test.js` prompt izinleri ve öncelik sırasını test ediyor. İlk `blocked` cevabı sözleşmeye uygun bir sonuçtu.

3. **Salt-okunur snapshot path kaçışı/root rebinding:** Son dosyaya yalnızca `lstat` uygulamak, üst dizin symlink/junction'ının dış dizine gitmesini engellemiyordu; snapshot ölçümü/kopyası path'i izleyebilirdi. Workspace kökü yeniden bağlanırsa yeniden çözümlenen kök de sınırı kaydırabilirdi. `parallel-batch.js` artık canonical kök path/device/inode kimliğini tutuyor, her path bileşenini ve descriptor kimliğini okuma öncesi/sonrası kontrol ediyor. `git-worktree-batch.js` source workspace için de anchor tutuyor. `parallel-batch.test.js` üst dizin symlink'i ve kök rebinding senaryolarını reddediyor. OS tarafından atomik directory handle kullanılmadığından, kötü niyetli yerel süreçlerin pathname kontrolleri arasında swap yapmasına karşı mutlak confinement iddia edilmiyor.

4. **Opsiyonel diff limitlerinde edit prompt `ReferenceError`:** Top-level `buildEditWorkerPrompt`, service factory scope'undaki `batchConfiguration` adına doğrudan erişiyordu; schema'da task diff limitleri opsiyoneldi. Üç sınırdan biri verilmezse prompt oluşturma aşaması `ReferenceError` üretebiliyordu. Builder artık config'i açık argüman alıyor ve task → host → sabit varsayılan sırasıyla çözüyor. `parallel-batch-integration.test.js` üç task sınırı olmadan edit prompt'un host tavanlarını kullandığını test ediyor.

5. **İptal sonrası onay ve cancel/approve yarışı:** Önceki `cancel()` `ready_for_approval` durumunu terminal yapmıyordu; geçerli approval diff'i uygulayabiliyordu. Ayrıca karar ilk manifest okuması ile registry mutation arasında değişebilirdi. Cancel artık ready approval'ı `cancelled` yapıyor; approve registry kilidi altında önce `integrating` claim ediyor; cancellation mutasyonu güncel durumu aynı kilit içinde yeniden denetliyor. `parallel-batch.test.js` stale cancellation'ın, `parallel-batch-integration.test.js` iptal/approval sırasının kaynak dosyayı değiştirmediğini doğruluyor.

6. **Task Promise reddi ve terminal registry update reddi:** Eski `Promise.allSettled` sonuçları işlenmiyordu; reddedilen task `running` kalabilir ve batch `result_ready` olabilirdi. Ayrıca terminal task mutation sonucu başarısız olduğunda `taskStatus === "running"` şartlı kontrol ölüydü; gerçek `taskStatus` o noktaya geldiğinde terminal değere çevrilmiş oluyordu. Artık terminal mutation reddi task Promise'ini reject ediyor, wave sonucu `unknown`/`failed` durumuna uzlaştırılıyor ve unknown allocation korunuyor. RunBatch durum geçişleri de reddedilirse outer fail-closed uzlaştırmaya aktarılıyor. Hata enjeksiyonu testleri artifact-store failure ve terminal state mutation rejection yollarını kapsıyor.

7. **Task diff'in bellekten temizlenmemesi:** `heldDiffs` yalnızca `prepareIntegration` başladığında temizleniyordu; bir edit task başarılı olup aynı batch'teki başka task fail/cancel olursa entegrasyon hazırlığı çalışmıyor ve diff bellekte kalıyordu. Diff'ler artık her batch terminalinde, dış batch hata yolunda ve `prepareIntegration`'ın tüm dönüşlerinde temizleniyor. `parallel-batch.test.js` entegrasyona geçemeyen karma edit batch'inde release callback'ini doğruluyor; worktree testleri ikinci hazırlamada consumed diff'i göremediğini doğruluyor.

8. **Edit fallback allocation'ının gerçek yürütme rotasıyla uyuşmaması:** Profile fallback'leri `computeAllocation`'da hesaplanırken parallel runtime fallback yürütmesi yalnız read-only profil görevlerinde etkin. Edit profilindeki kullanılmayacak fallback'ler admission estimate'i gereksiz büyütebiliyordu. Tahmin artık fallback rotalarını yalnız read-only mod için ekliyor; `parallel-batch-integration.test.js` edit profili fallback'lerini çalıştırmayacağı halde gereksiz rezervasyon istemediğini test ediyor. Codex gerçek `totalCostUsd` sağlamadığından unknown cost allocation'ın tutulması ayrı ve bilinçli muhasebe davranışıdır; bu geçmiş auth hatasının nedeni değildir.

9. **Çok dosyalı promotion sürecinin kesilmesinde kısmi değişiklik:** Dosyalar tek tek değişiyor; yalnız bellek içi rollback process termination'da çalışmazdı. Promotion öncesi workspace'e bağlı journal önceki ve hedef içerik/hash'lerini kalıcı yazar; commit marker batch/workspace/diff/journal hash'lerine bağlanır ve registry entegrasyon manifesti uzlaştırılana kadar korunur. Başlangıç recovery'si kısmi değişikliği geri alır; committed marker'ı aynı workspace/diff manifestiyle registry kilidi altında eşleştirir. Workspace'ler journal ve batch recovery sırasında hash'le ayrılır. `parallel-batch-worktree.test.js` gerçek child-process termination ve marker-only cleanup senaryolarını; `parallel-batch.test.js` manifest hash uyuşmazlığı ile lock-arası mutasyonu test ediyor. `fsync` sınırlamaları nedeniyle makine/güç kaybı dayanıklılığı garanti edilmiyor; dış okuyucular dosyaları tek tek değişirken ara durumu görebilir.

10. **Ortak registry'de workspace'ler arası batch erişimi/kurtarma:** Registry ortak state dizini kullanıyor. Workspace binding olmadan batch ID ile summary, detail, cancel, start/recovery başka workspace manifestine ulaşabilirdi. Yeni plan/batch'ler `workspaceHash` taşır; servis işlemleri bu hash'i kontrol eder, registry recovery de hash olmadan çalışmayı reddeder. Cross-workspace testleri diğer workspace'in summary, detail, cancel, plan start ve interrupted recovery isteklerini sınar. `workspaceHash` taşımayan eski interrupted kayıtlar otomatik sahiplenilmez; scoped recovery bunları sayar ve servis fail-closed döner.

## Ne yaptık ve düzeldi mi (teknik)

Aşağıdaki durumlar güncel kaynak okuması ve regresyon testleriyle doğrulandı. `Düzeldi` etiketi ilgili mekanizmanın kaynakta değiştirildiğini ve bir testin o davranışı bağladığını; `Kısmi` etiketi düzeltmenin kapsam sınırını; `Unknown` etiketi ise artık geri getirilemeyen geçmiş provider çıktısına bağlı olarak doğrulanamayan durumu belirtir.

1. **Codex auth yanlış-pozitif sınıflandırması — Düzeldi; tarihsel neden Unknown.** `codex-adapter.js:46` artık yalnız belirgin authentication-failure ifadelerini eşleştiriyor; çıplak `auth/login/credential/unauthorized/api.key` alt dizesi kaldırıldı ve `author`/`authorization`/`oauth` negatif vakaları `tests/faz-3-codex.test.js:27-51` ile bağlandı. 2026-10-05 olayının ham stdout/stderr'i yok; bu nedenle gerçek olayın yanlış pozitif mi yoksa gerçek bir provider auth hatası mı olduğu bilinemez. Değişiklik kontrol akışını değil yalnız `failureClass`/`reason` etiketini etkiler; `auth_invalid` yine retry-dışıdır.

2. **Prompt kaynaklı `blocked` — Düzeldi (görev sözleşmesi).** Read-only prompt `parallel-batch.js:264` ile listelenmiş snapshot'ı read-only araç/komutla okumaya izin verir, `:267` ile task-specific stop condition'ların önceliğini korur; `tests/parallel-batch.test.js:485-515` izin ve öncelik sırasını doğrular. İlk `blocked` sonucu provider arızası değil, sözleşmeye uygun bir duruştu.

3. **Snapshot symlink/root rebinding — Düzeldi; eşzamanlı yerel swap için Kısmi.** `parallel-batch.js:64` `createWorkspacePathAnchor` canonical path + device/inode sabitler; `:86` `inspectWorkspaceFile` her path bileşenini `lstat`/`realpath` ile denetler; `:150` `readContainedWorkspaceFile` descriptor ile okur ve önce/sonra inode/dev/size/mtime/nlink karşılaştırır. `git-worktree-batch.js:147` `inspectSourcePath` ve `:132` source anchor aynı korumayı promotion kaynağına uygular. `tests/parallel-batch.test.js:618` üst dizin symlink'ini, `:646` kök rebinding'i reddeder. Pathname kontrolleri atomik bir directory handle'a sabitlenmediğinden, kontroller arasında pathname swap-and-restore yapan kötü niyetli yerel sürece karşı mutlak yarışsız confinement iddia edilmez.

4. **Edit prompt `ReferenceError` — Düzeldi.** `buildEditWorkerPrompt` `parallel-batch.js:278` artık `batchConfiguration`'ı açık parametre alır ve task → host → sabit varsayılan sırasını `??` ile çözer; çağrı `:1181`. `tests/parallel-batch-integration.test.js:195` üç task limiti verilmediğinde host tavanlarının prompta yazıldığını doğrular. Önceki top-level scope erişimi opsiyonel limitlerde `ReferenceError` üretebiliyordu.

5. **Cancel/approve yarışı ve iptal sonrası onay — Düzeldi.** Onay `registry.updateBatch` kilidi altında önce `integrating` claim eder; cancellation mutasyonu güncel durumu aynı kilit içinde reddeder. `tests/parallel-batch.test.js:1118` stale cancellation'ın integrate claim'ini geçersiz kılamadığını, `tests/parallel-batch-integration.test.js:216` iptal edilen hazır diff'in onaylanamadığını ve kaynağın değişmediğini doğrular.

6. **Task Promise reddi ve ölü terminal-mutation guard'ı — Düzeldi.** `parallel-batch.js:1364` terminal registry mutation reddini artık exception ile `Promise.allSettled` akışına taşır; `:1391` `runBatch` reddedilen wave sonuçlarını `:984` `markUnexpectedTaskFailure` ile `unknown`/`failed` durumuna uzlaştırır ve unknown allocation'ı korur. Ayrıca `:1051` `requireBatchUpdate` eklenerek batch durum yazımları (`:1393`, `:1413`, `:1457`, `:1477`, `:1499`, `:1512`) denetimsiz bırakılmadı. `tests/parallel-batch.test.js:686` artifact-store failure'ını, `:701` reddedilen terminal mutation'ı bu yollarla doğrular. Eski guard `taskStatus === "running"` şartına bağlıydı ve o noktada status zaten terminal olduğundan ölüydü.

7. **`heldDiffs` bellek sızıntısı — Düzeldi.** `git-worktree-batch.js:678` `releaseBatchTaskDiffs` batch önekli tüm girişleri siler; `:685` `prepareIntegration` tüm dönüş/istisna yollarında `finally` ile temizler; `parallel-batch.js:927` ve `:1521` normal ve beklenmedik batch sonunda temizliği çağırır. `tests/parallel-batch.test.js:290` entegrasyona gidemeyen karma edit batch'inde release'i doğrular; worktree testleri ikinci hazırlamada tüketilmiş diff'in bulunmadığını kapsar.

8. **Edit fallback allocation uyuşmazlığı — Düzeldi.** `parallel-batch.js:569` `computeAllocation` fallback rotalarını yalnız `:571` `read_only` modda ekler; edit görevleri için runtime fallback yürütmesi zaten yoktur. `tests/parallel-batch-integration.test.js:353` edit profilinde tanımlı fallback olsa da admission tahminin primary route maliyetiyle sınırlı kaldığını doğrular. Not: gerçek `totalCostUsd` bilinmeyen Codex çağrılarında unknown allocation'ın tutulması ayrı, kasıtlı muhasebe kuralıdır.

9. **Çok dosyalı promotion süreç kesintisi — Düzeldi; makine/güç kaybı için Kısmi.** `git-worktree-batch.js:207` `writePromotionJournal` önceki/hedef içerik-hash'lerini kalıcı yazar; `:328` `recoverPromotionJournal` conflicting değişiklikte fail-closed kalır; `:384` `finalizePromotion` workspace/diff binding'ini doğrular ve marker'ı registry uzlaşmasına kadar korur. Servis tarafı uzlaştırma `parallel-batch.js:1766-1786`. Testler: `tests/parallel-batch-worktree.test.js:269` child-process termination rollback'i, `:329` committed marker'ın restart'ta korunmasını; `tests/parallel-batch.test.js:730`, `:826`, `:877` manifest binding ve kilit-arası mutasyonu. `fsync`/dizin senkronu platform sınırları nedeniyle güç kaybı dayanıklılığı garanti edilmez; dış okuyucular dosyaları tek tek değişirken ara durumu görebilir.

10. **Çapraz-workspace erişim/kurtarma — Düzeldi; legacy kayıtlar için Kısmi.** Plan/batch'ler `workspaceHash` taşır ve servis işlemleri bunu denetler; `parallel-batch-registry.js:182` `recoverInterruptedBatches` workspace hash olmadan `workspace_hash_required` döner, yabancı workspace'i atlar ve hash'siz interrupted kayıtları `unscopedCount` ile sayar; `parallel-batch.js:1799` servis bunu fail-closed raporlar. Testler `tests/parallel-batch-state.test.js:135` ve `tests/parallel-batch.test.js:240` izolasyonu doğrular. `workspaceHash` içermeyen eski interrupted kayıtlar otomatik sahiplenilmez; yönetilen migration gerekir.

## Kaynakta bulunan ama bilinen hataların tarihsel nedeni olmayan adaylar

- Worker JSON özeti çıkarıcısının ilk `{` ile son `}` arası metni ayrıştırması, sözleşme dışı prose içinde brace bulunursa `schema_invalid` üretebilir. Worker promptu tam JSON ister; bu mekanizma tarihsel `auth_invalid` veya prompt kaynaklı `blocked` olayını açıklamıyor ve bu analizde değişmedi.
- `webEvidence` excerpt'larının provider kaynağıyla kriptografik olarak ilişkilendirilmesi bu görevde doğrulanmadı. Bu, untrusted evidence doğrulama sınırıdır; incelenen eski Codex hata olaylarının nedeni olarak sunulmuyor.

## Üç modelin katkısının niteliği

- Gemini 3.8 Flash auth/preflight yarışı gibi olasılıkları hipotez olarak sundu; raw auth çıktısı yokluğunda kesin kök neden iddia etmedi. Doğru şekilde hipotez seviyesinde tutuldu.
- Space Bunny Free daraltılmış review'da `heldDiffs` yaşam döngüsü ve reddedilen batch/task state mutation yollarını işaret etti. Geniş ilk incelemesi timeout oldu; daraltılmış görev başarılı sonuç verdi. Kod akışları yukarıdaki şekilde bağımsız doğrulandı ve gerekli yerlerde düzeltildi.
- DeepSeek V4 Pro regex, prompt, retry, settlement ve test kapsamını kaynak akışında ayırdı. Çıktısındaki ek adaylar ham geçmiş provider çıktısı yerine geçmedi; yalnız kodda gösterilebilir mekanizmalar rapora alındı.

## Son durum ve açık kapılar

Hedefli V2 test grubu (`parallel-batch.test.js`, `parallel-batch-integration.test.js`, `parallel-batch-worktree.test.js`, `parallel-batch-state.test.js`, `parallel-batch-registry.test.js`, `parallel-batch-budget.test.js`) 79/79 geçti. Son tam yerel doğrulama `npm test` 859/859, `npm run verify`, `npm run verify:ci`, `npm run smoke`, `npm run drill` 8/8, sentetik DeepSeek V4 Pro salt-okunur `npm run pilot` ve `git diff --check` başarılıdır. Pilot tek bir stdio MCP çağrısında yapılandırılmış JSON sonucu verdi; bildirilen 0.017589 USD Bridge maliyet ölçümüdür, provider invoice değildir. GPT-6.1 Sol'un son read-only follow-up'ı kaynak kusurlarını ve root cause ayrımını doğruladı; testleri kendisi çalıştırmadı.

V2 varsayılan olarak kapalıdır (`parallelBatch.enabled=false`, `editEnabled=false`). Remote-write denial `unproven`; OpenCode `steps` `unavailable`; iki task'lı canlı edit pilotu ve host verification allowlist'i yok. Bu rapor bu kapıları açmaz ve provider remote-write/live-edit başarısı iddia etmez. Önceki raw Codex `auth_invalid` olayı unknown kalır; sınıflandırıcı yanlış pozitif kaynağı giderilmiştir ama eski provider çıktısı olmadan olayın gerçek nedeni belirlenemez.
